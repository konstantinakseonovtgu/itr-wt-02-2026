## Основное задание. Интернет-магазин

Предметная область — интернет-магазин.

1. Придумать классы, которые описывают сущности интернет-магазина: продукт, корзина, отзыв, пользователь, форма обратной связи и т. д.
2. Описать состояние классов из п. 1 — атрибуты экземпляра.
3. Описать поведение классов из п. 1 — методы.
4. Придумать наследников классов из п. 1. Чем они будут отличаться?

Файл `shop.py`, запуск: `python shop.py`. Внизу файла — несколько строк, которые создают объекты, вызывают методы и печатают результат через `print`.

Критерии приёмки:

- не меньше пяти классов предметной области (например, `Product`, `Cart`, `Review`, `User`, `FeedbackForm`), у каждого — докстринг с одной фразой «что это»;
- состояние: атрибуты создаются в `__init__` через `self`, а не в теле класса; изменяемые коллекции (товары в корзине, отзывы у товара) — свои у каждого объекта;
- поведение: у каждого класса хотя бы один осмысленный метод, который работает с состоянием объекта (`Cart.add()`, `Cart.total()`, `Review.is_positive()`, `FeedbackForm.send()`…), а не просто печатает строку;
- инкапсуляция: хотя бы два атрибута с проверкой через `@property` (цена больше нуля, оценка отзыва от 1 до 5, email содержит `@`); при неверном значении — `ValueError`; значение хранится в `_x`;
- наследование: хотя бы два наследника, и в докстринге каждого — ответ на вопрос п. 4 «чем отличается» (например, `DigitalProduct` без доставки, `HeavyProduct` с доставкой по весу, `Admin(User)` может удалять отзывы). Наследник переопределяет метод или добавляет свой; если у наследника свой `__init__`, он вызывает `super().__init__(...)`;
- полиморфизм: один цикл вызывает один и тот же метод у объектов разных классов (например, стоимость доставки у разных товаров) без проверки типа через `if`;
- композиция: хотя бы один класс хранит объекты других классов (корзина — товары, отзыв — пользователя и товар);
- имена в `snake_case` для методов и атрибутов, `PascalCase` для классов; сообщения исключений на английском.

## Дополнительные упражнения

По желанию или для тех, кто быстро справился с основным заданием. Файл `homework1.py`, запуск `python homework1.py`.

### Упражнение 1. `BankAccount`

Класс `BankAccount` с конструктором `__init__(self, owner, balance=0)` и свойством `balance`. Сеттер запрещает отрицательный баланс: бросает `ValueError`. Добавить методы `deposit(amount)` и `withdraw(amount)`; снятие больше остатка должно приводить к `ValueError` (через сеттер).

Критерий приёмки:

- `acc = BankAccount("Анна", 100)`; `acc.balance` даёт `100`;
- `acc.balance = -5` бросает `ValueError`, баланс остаётся прежним;
- `acc.withdraw(500)` бросает `ValueError`, `acc.deposit(50)` увеличивает баланс до `150`;
- значение хранится в `_balance`, сеттер не вызывает сам себя; `BankAccount("Анна", -1)` тоже даёт `ValueError`.

### Упражнение 2. Иерархия `Shape → Circle/Rectangle`

Базовый класс `Shape` с методом `area()`; в базовом классе он бросает `NotImplementedError`. Подклассы `Circle(radius)` и `Rectangle(width, height)` переопределяют `area()`. Для числа π использовать атрибут класса (например, из `MathOperation.PI` или собственный).

Критерий приёмки:

- `Circle(2).area()` близко к `12.56` (при `PI = 3.14`), `Rectangle(3, 4).area()` равно `12`;
- `Shape().area()` бросает `NotImplementedError`;
- цикл `for s in (Circle(1), Rectangle(2, 5)): print(s.area())` печатает площади без проверки типа;
- `isinstance(Circle(1), Shape)` и `isinstance(Rectangle(2, 5), Shape)` дают `True`; `Circle` и `Rectangle` наследуются от `Shape` (`Shape` указан в скобках).

### Упражнение 3. Композиция `Library` и `Book`

Класс `Book(title, author)` и класс `Library`, который хранит коллекцию книг в атрибуте-списке. Методы: `add_book(book)`, `find_by_author(author)` (возвращает список книг), `count()`.

Критерий приёмки:

- список книг создаётся в `__init__`, а не в теле класса: две библиотеки не делят книги (проверка: `l1.add_book(b)`; `l2.count()` равно `0`);
- `Library` не наследуется от `Book` и не наоборот;
- `find_by_author` возвращает пустой список, если книг нет;
- `add_book` принимает только `Book`: при другом типе бросает `TypeError` (проверка через `isinstance`).

Общее требование ко всем задачам: имена методов и атрибутов в `snake_case`, внутренние атрибуты с `_`, в конце файла несколько строк с примерами вызова и выводом через `print`.
